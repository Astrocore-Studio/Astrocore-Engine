# Измерения производительности

Бюджеты (время кадра, тика сервера, память на регион, стоимость пересборки чанка,
трафик на игрока) по разделу 19 дизайн-документа **не фиксируются**, пока нет целевого
железа и репрезентативных сцен. Здесь — воспроизводимый набор сценариев и результаты
первого прогона, чтобы видеть тенденции и ловить регрессии.

Запуск (число кварталов задаёт размер города):

```bash
cargo run --release -p astrocore-tools -- bench --blocks 8
```

## Результаты (release, 4 ядра CPU, контейнер без GPU)

Город 8×8 кварталов, 3840 структурных элементов, один этаж:

## Что из этого следует

* Шаг движения игрока ≈ 24 мкс: 50 игроков при 20 Гц — около 24 мс процессорного времени
  в секунду на физику (≈ 2,4 % одного ядра).
* Сервер целиком (приём, движение, интерес, рассылка) — ≈ 17 мкс на команду игрока при 50 игроках.
* Повторная сборка карты «из кэша» всё ещё стоит ≈ 16 мс: чанки берутся из кэша, но
  топология и сериализация пакетов пересчитываются целиком — следующий шаг оптимизации.
* Рендер здесь не измерялся: в среде нет GPU (программный Vulkan непоказателен).

Числа зависят от машины; сравнивать имеет смысл только прогоны на одной конфигурации.
