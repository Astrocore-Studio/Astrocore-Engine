# Сохранения

Модель: **снимок + журнал**.

```
data/
├── snapshot.json    контрольная точка (атомарно: tmp → fsync → rename)
└── journal.jsonl    операции после снимка: "<crc32 hex> <json WorldOp>\n"
```

* `Store::save_snapshot` пишет снимок и очищает журнал. Сбой между `rename` и очисткой
  безопасен: повтор журнала пропускает уже учтённые операции (идемпотентность по `seq`).
* `Store::append` пишет операцию с `sync_data`.
* `Store::recover` = снимок + повтор журнала.

## Недоверенные данные

Снимок проходит: проверку `format_version` и миграции → разбор → `World::from_state`
(полная валидация) → сверку ревизии → сверку `content_hash`. Журнал: CRC каждой
строки; оборванная **последняя** строка (сбой при записи) отбрасывается и
отмечается в отчёте; повреждение **в середине** — ошибка; пропуск `seq` — ошибка;
операция, не применимая к снимку, — ошибка. Журнал без снимка не принимается.

## Миграции

`Migrator`: шаг `from` переводит документ версии `from` в `from + 1`. Текущая версия
формата — 1, шагов пока нет. Правило: **любое** изменение схемы = новая версия +
шаг миграции + golden-файл старой версии (`crates/astrocore-persistence/tests/golden_snapshot_v1.json`,
тест `golden_v1_snapshot_still_loads`). Генератор golden-файла: тест
`generate_golden` (`--ignored`), запускать только осознанно.

## Пока не реализовано

Миграция динамического состояния при обновлении **авторской карты** (раздел 10.2/18
дизайн-документа): отчёт о конфликтах между картой N+1 и пользовательскими
изменениями. Сохранение runtime-состояния симуляций (двери, газы, электричество) —
вместе с появлением этих систем.
