# ADR-0010. Lightyear как транспорт, состояние остаётся у Astrocore

* Статус: **принято**
* Дата: 2026-11-11
* Дополняет: ADR-0006 (собственные TCP и UDP остаются)

## Решение

`astrocore-lightyear` использует Lightyear 0.31.0 (UDP + netcode) как транспортный слой: пакеты
протокола `astrocore_protocol` передаются сообщением `AstroPacket(Vec<u8>)` по двум каналам —
надёжному упорядоченному (вход, снимки, структурные операции, двери, содержимое) и
последовательному ненадёжному (ввод, состояние сущностей). Владение состоянием, валидация пакетов,
интерес, предсказание и согласование остаются у Astrocore (как требует раздел 4 дизайн-документа:
«Lightyear + Astrocore Protocol; state ownership у Astrocore»). Репликация сущностей Lightyear
(`Replicate`) **не используется**: мир реплицируется своими операциями и снимками.

Приложения: сервер `--listen-lightyear адрес --ly-key hex32`, клиент `--connect-lightyear адрес
--ly-key hex32`. `LyGameHost` связывает приём, тики `GameServer` и отправку.

## Ограничения

* Аутентификация netcode — **общий секрет** (`Authentication::Manual`): годится для разработки и
  закрытых серверов. Для публичной игры нужен бэкенд выдачи connect-токенов (в движок не входит).
* Шифрование — на уровне netcode; собственный защищённый UDP (`--listen-udp`) остаётся
  альтернативой с закреплённым ключом сервера.
* Lightyear собирает Bevy-приложение внутри транспорта (без окна); накладные расходы не измерялись.
* Предсказание и интерполяция Lightyear не подключены: у Astrocore свои.

## Проверки

Сквозные тесты по loopback: вход, получение снимка мира, ввод по ненадёжному каналу, пакеты до
завершения рукопожатия ставятся в очередь, неверный ключ не подключается, таймаут освобождает слот;
запуск `astrocore-server` и `astrocore-client` через Lightyear.
