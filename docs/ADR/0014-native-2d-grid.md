# ADR-0014. Нативный 2D-мир Astrocore

Astrocore переходит на 2D как основное направление. У тайла целочисленные координаты
по X и Y. Положение подвижного объекта непрерывно и выражено в тайлах, ось Y направлена
вверх. Engine отвечает за сетку, коллизии и сетевой сеанс. Build определяет игровой
контент и правила.

Клетка и положение объекта включают целочисленный Z. Этажи имеют собственные
размеры и наборы тайлов. Движение в плоскости сохраняет Z, а Build меняет его
при прохождении по заданному на карте переходу. Станция использует Z в
проверках дальности, кабельных сетях и газовых связях. Клиент и редактор
отображают выбранный этаж как 2D-сетку.

`astrocore-grid2d` принимает ввод, выполняет серверный тик 20 Гц и рассылает
состояние. Сеанс использует существующий транспорт Lightyear с отдельной версией
протокола. Идентификатор протокола включает версии сеанса Engine и данных игры.
Build увеличивает версию своих данных при несовместимых изменениях карты,
команд или снимка. При входе сервер передаёт подготовленную карту с каталогом
частями по 8 КиБ по надёжному упорядоченному каналу. Затем сервер отправляет
первый снимок состояния. Игра открывается после получения карты и снимка.
Клиент подтверждает последний применённый тик. Сервер отправляет дельты
от подтверждённого тика по последовательному ненадёжному каналу и переиспользует
пакет для клиентов с одинаковой базой. Дельты включают добавление, обновление
и удаление записей. Клиент применяет дельту к состоянию указанного тика.
Обе стороны хранят историю на 32 тика. Когда подтверждённая база выпадает
из истории, сервер отправляет новый полный снимок по надёжному каналу.
При частоте 20 Гц это происходит до трёхсекундного тайм-аута соединения.

Схема подтверждения тиков и обновлений опирается на `GameState` и
`ServerGameStateManager` из версии Robust, закреплённой в NightCity.
Astrocore отправляет изменения всей станции. Отбор видимых сущностей остаётся
отдельным этапом переноса.
[GameState.cs](https://github.com/space-wizards/RobustToolbox/blob/4058566ed460e156d77d32b1810fd97ba5a57ff9/Robust.Shared/GameStates/GameState.cs)
[ServerGameStateManager.cs](https://github.com/space-wizards/RobustToolbox/blob/4058566ed460e156d77d32b1810fd97ba5a57ff9/Robust.Server/GameStates/ServerGameStateManager.cs)

Build загружает станцию и прототипы из RON. Карта и каталог передаются при входе.
Сервер проверяет движение, дальность действий, занятость проёмов и состояние рук.
Сеанс Engine принимает типизированные игровые команды Build по надёжному
каналу и держит до 16 команд на игрока. Симуляция применяет их в порядке
получения по одной за тик. По последовательному каналу приходит последнее
направление движения. Build ведёт фазы раунда,
атмосферу и питание, а графический клиент отображает состояние сервера.

В раунде Build изменяет рабочую копию тайловой сетки. Сервер использует её
для коллизий и пересчёта газовых рёбер. В снимок входят изменения к исходной
сетке и их ревизия. При новом раунде Build восстанавливает исходную сетку.
Редактор сохраняет исходную карту в формате загрузчика Build.

Активная сборка проекта — 2D. Корневая команда `cargo play` в Build запускает
локальный сервер и клиент. План разрушаемого 3D-мира из ADR-0004 Build
относится к истории проекта.
