# ADR-0015. Ядро сущностей по образцу Robust Toolbox

Дата: 2026-11-26. Статус: принято владельцем.

## Контекст

Цель проекта — Space Station 14 на Rust: движок переносит Robust Toolbox, Build — контент SS14.
Референс закреплён в `docs/REFERENCE.md` Build. Сервер рассчитан на 160+ игроков.

`astrocore-grid2d` (ADR-0014) хранит состояние игры одной структурой Build и реплицирует её
целиком. В SS14 всё — сущности с компонентами: тысячи прототипов и больше десяти тысяч сущностей
на карте. Чтобы переносить системы SS14 по одной, движку нужны сущности, компоненты, системы,
события, прототипы и репликация по компонентам.

## Решение

### 1. Хранилище — `bevy_ecs`, события — своя шина

Сущности и компоненты хранит `bevy_ecs::World`. Идентификатор сущности движка — `Entity` Bevy.
Запросы, отслеживание изменений и многопоточное расписание систем берём у Bevy.

Направленные события Robust (`RaiseLocalEvent(uid, ref ev)`) синхронны, вложены и отменяемы.
Наблюдатели Bevy изнутри обработчика событие синхронно поднять не могут (`DeferredWorld`
откладывает его в команды), поэтому события ведёт собственная шина `EventBus`:

* подписка — пара «компонент + событие» или широковещательная, с порядком `before/after`;
* обработчик — функция `fn(&mut World, Entity, &mut E)`; она без состояния, поэтому
  вложенные и рекурсивные события допустимы;
* событие доходит до обработчиков тех компонентов, которые есть у сущности.

Многопоточность:

* тяжёлые расчёты (атмосфера, питание, физика, сбор сетевых состояний) — обычные системы Bevy
  с запросами и параллельные итераторы; расписание Bevy исполняет их на всех ядрах;
* игровая логика, которой нужны синхронные события, — исключающие системы (`&mut World`),
  они исполняются последовательно между параллельными этапами.

### 2. Жизненный цикл как в Robust

`MetaData.stage`: `Spawned → Initialized → Started → MapInitialized → Terminating`.
События компонентов: `ComponentAdd`, `ComponentInit`, `ComponentStartup`, `MapInit`,
`ComponentShutdown`, `ComponentRemove`. Удаление сущности откладывается до конца тика.
`MapInit` приходит только на инициализированной карте; сущности карты на паузе не тикают.

### 3. Этажи Z встроены в ядро

Robust плоский. Astrocore — нет: решение владельца.

* Координата тайла — `(x, y, z)`, `z: i16` — этаж.
* `Transform` хранит локальную позицию `Vec2`, поворот и локальный этаж `z` относительно
  родителя. Мировой этаж — сумма по цепочке родителей.
* Грид хранит чанки 16×16 по ключу `(chunk_x, chunk_y, z)`. Карта SS14 загружается на `z = 0`.
* Физика сталкивает тела только одного этажа. PVS и атмосфера работают по этажам; связи между
  этажами (проёмы, лестницы) задаёт Build.

### 4. Прототипы: YAML и RON, одно дерево данных

Оба формата разбираются в общее дерево `DataNode`; дальше работают наследование Robust,
реестр компонентов и `serde`.

* YAML — формат SS14: файлы `Resources/Prototypes` и карты читаются без конвертации. Это путь
  для переноса контента из сборок SS14.
* RON — стандарт собственного контента Astrocore: та же структура, синтаксис RON; полиморфные
  значения (`!type:Foo` в YAML) записываются как `Foo(...)`.
* Компонент — тип Rust с `serde::Deserialize` и именем в реестре. Прототип после наследования
  разбирается один раз; при создании сущности компоненты клонируются.

### 5. Репликация по компонентам и PVS

Схема тиков, подтверждений и дельт ADR-0014 сохраняется, но единица репликации — состояние
компонента сущности. Изменения находит отслеживание изменений Bevy; сервер отправляет клиенту
только сущности из чанков вокруг его глаз (PVS). Сбор состояний идёт параллельно по сессиям.

### 6. Состав крейтов

| Крейт | Содержание | Аналог в Robust |
|---|---|---|
| `astrocore-data` | `DataNode`, разбор YAML и RON, `serde` | `Robust.Shared/Serialization` |
| `astrocore-ecs` | жизненный цикл, `MetaData`, события, системы, время, контейнеры, реестр компонентов | `Robust.Shared/GameObjects`, `Timing`, `Containers` |
| `astrocore-prototypes` | виды прототипов, наследование, создание сущностей | `Robust.Shared/Prototypes` |
| `astrocore-map` | `Transform`, карты, гриды с этажами, тайлы | `Robust.Shared/Map` |
| `astrocore-console` | CVar и консольные команды | `Robust.Shared/Configuration`, `Console` |
| `astrocore-transport` | Lightyear: соединения и каналы | `Lidgren`, `Robust.Shared/Network` |
| `astrocore-net` | состояния компонентов, PVS, сетевые события | `Robust.*/GameStates` |
| `astrocore-physics` | тела, фикстуры, слои столкновений | `Robust.Shared/Physics` |
| `astrocore-client` | спрайты RSI, камера, свет, звук, UI, ввод | `Robust.Client` |
| `astrocore-grid2d` | сеанс ADR-0014 до переноса Build | — |

## Последствия

* Системы SS14 переносятся почти один к одному: компонент → `struct` с `Component`, подписка
  `SubscribeLocalEvent<TComp, TEvent>` → `bus.subscribe::<TComp, TEvent>(handler)`.
* Обработчики событий получают `&mut World` и исполняются последовательно. Параллельность
  достигается расписанием систем и параллельными расчётами, а не обработчиками.
* Build переезжает с `astrocore-grid2d` на новое ядро по механикам; после переезда
  `astrocore-grid2d` удаляется.
