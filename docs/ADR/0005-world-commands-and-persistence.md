# ADR-0005. Команды мира, ревизии и сохранения

* Статус: **принято**
* Дата: 2026-11-10

## Решение

1. Единственный способ изменить мир — `WorldCommand`. Валидация целиком до мутации.
2. Ревизия мира = число применённых команд; `WorldOp.seq` = ревизия после применения.
   Это даёт идемпотентность (повтор), обнаружение пропусков и один механизм для журнала,
   сети и восстановления.
3. Dirty-регионы — чанк × этаж с флагами пересборки; ревизии чанков хранятся в состоянии.
4. Сохранение = атомарный снимок + журнал с CRC32; повтор журнала пропускает учтённое.
5. Формат снимка версионирован; изменение схемы = новая версия + миграция + golden-файл.
6. Хеш содержимого (FNV-1a 64 по каноническому JSON) — для сверки миров, не для безопасности.

## Рассмотренные варианты

* **Snapshot-only:** теряет операции между снимками.
* **Event-sourcing без снимков:** долгий старт.
* **Бинарный формат снимка:** отложен — читаемый JSON удобнее для отладки и миграций;
  вернёмся к вопросу по измерениям (компилируемые бинарные пакеты — F6).

## Последствия

Хеш содержимого зависит от сериализации чисел с плавающей точкой; он стабилен для
одной версии формата, поэтому изменение схемы всегда сопровождается golden-тестом.
