# ADR-0011. Воксельные модели

* Статус: **принято**
* Дата: 2026-11-18

## Контекст

Игровые билды переходят на воксельную графику: сущности (персонажи, одежда, предметы, мебель)
рисуются воксельными моделями вместо направленных спрайтов (ADR-0007); тайлы и структурная сетка
остаются. Моделей пока нет — их рисуют в MagicaVoxel (уточнено 19.11.2026: своего
редактора вокселей в Studio не будет, движок читает `.vox` напрямую) и получают
автоматически из спрайтов (это забота билда). Движку нужны формат, проверка недоверенных файлов,
импорт из внешнего редактора и сборка меша.

## Решение

* **Крейт `astrocore-voxels`**, без Bevy и GPU: модель, кодек, импорт `.vox`, сборка меша. Рендер
  (компонент, кэш сеток, материалы) — в `astrocore-render` поверх него; сервер может читать
  модели (габариты для коллизий), не таща графику.
* **Модель** — плотная сетка `size = [x, y, z]` (каждая сторона 1…256) индексов палитры
  (`0` — пусто, `1…255` — цвета RGBA sRGB), масштаб `voxels_per_meter` (по умолчанию **32**: один
  воксель — один пиксель спрайтов SS14) и точка опоры `pivot` в вокселях (по умолчанию — центр
  основания: `[x/2, 0, z/2]`).
* **Оси** — как во всём движке (ADR-0003): Y вверх, правосторонняя система. Перед модели смотрит в
  **+Z** (к камере по умолчанию, как лицевая сторона спрайта), правая сторона модели — **−X**
  относительно зрителя спереди, то есть X картинки «спереди» идёт слева направо.
* **Файл `.avox`** (версия 1, little-endian): `"AVOX"`, `u16` версия, `[u16; 3]` размер,
  `u16` вокселей на метр, `[f32; 3]` опора, `u16` число цветов `n` (1…255) и `n` цветов RGBA,
  затем воксели порядком X → Y → Z сериями RLE (`u16` длина, `u8` индекс). Декодер проверяет
  размеры, длину серий, индексы и лимит 16 МиБ входа; ошибки типизированы, паник нет.
* **Импорт MagicaVoxel `.vox`** (версия 150+, первая модель, чанки `SIZE`, `XYZI`, `RGBA`):
  оси MagicaVoxel (Z вверх) переводятся поворотом `(x, y, z) → (x, z, size_y − 1 − y)`;
  без чанка `RGBA` берётся серая шкала. Поворот — единственное место преобразования осей
  (ADR-0003: только в импортёрах).
* **Сборка меша** — жадное объединение граней одного цвета в прямоугольники по каждому из шести
  направлений; внутренние грани не строятся. Результат — `VoxelMesh` (позиции в метрах
  относительно опоры, нормали, цвета вершин, индексы), независимый от Bevy.

## Последствия

* Модель — данные: прототип билда ссылается на файл модели, ручная модель заменяет
  сгенерированную без изменений кода.
* Анимация частями (руки, ноги) и LOD — отдельные решения; формат хранит одну неподвижную модель.
* Цвета вершин вместо текстур: материалы освещаются, но без UV; текстуры поверх вокселей не
  предусмотрены.
