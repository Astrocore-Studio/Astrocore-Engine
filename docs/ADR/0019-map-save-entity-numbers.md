# ADR-0019. Номера сущностей сохранённой карты для игры

Дата: 2026-11-27. Статус: принято (фаза 6, задача 6.6 плана Build: настройщик сети).

## Контекст

Компоненты SS14 ссылаются на другие сущности карты номерами файла: список устройств
воздушной тревоги (`DeviceList.devices`), связи сигналов (`DeviceLinkSource.linkedPorts`).
В Robust это делает сериализатор `EntityUid`: при сохранении ссылка пишется номером, который
сохранение выдало сущности.

У нас загрузчик отдаёт игре «номер файла → сущность» (`MapLoaded`), а ссылки, которые игра
понимает по-своему, сохраняются как были загружены (`MapPreserved`). Изменённые в игре
списки и связи (настройщик сети) в файл не попадают: игра не знает, какие номера получили
сущности в сохранении, — новые сущности получают номера только внутри `save_map`.

## Решение

1. **`MapSave::uids`** — соответствие «сущность → номер в сохранённом документе» для всех
   записанных сущностей. Игра после `save_map` дописывает ссылки своих компонентов этими
   номерами прямо в документ, как отдельный шаг (так же декали пишутся до сохранения).
2. **`DataNode::as_seq_mut`** — изменение последовательности документа на месте (рядом с
   `as_map_mut`), чтобы найти запись сущности по номеру и заменить поле компонента.

Номера стабильны, как и прежде: сущность из файла сохраняет свой номер, новые получают
номера после наибольшего.

## Последствия

- Ссылки на сущности в компонентах игры пишутся без знания движком их смысла.
- Ссылка на сущность вне сохраняемой карты не имеет номера в `uids` — игра её пропускает,
  как Robust пропускает ссылки на несохраняемые сущности.
